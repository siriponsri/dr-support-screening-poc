# แผน GPU window ใหม่สำหรับ PRISM (QA_SERVER, dr-train GPU0)

สถานะ: **เสนอให้ owner อนุมัติ** · 24 ตุลาคม 2569 · จัดทำโดย Claude Code · ต่อจาก HANDOFF §25–26

## 1. เป้าหมาย

พิสูจน์ PRISM จริงผ่านหน้าแอปให้ครบวงจร: เตรียมภาพ → ส่งโมเดล → บันทึกลง PostgreSQL → เปิดกลับมาแล้วผลยังอยู่
เริ่มจาก **1 เคส** ก่อน ถ้าผ่านครบจึงขยายอีก 2 เคส ไม่รัน batch เดิมซ้ำ

## 2. ขอบเขตที่ขออนุมัติ

| รายการ | ค่า |
| --- | --- |
| เครื่อง / GPU | dr-train เฉพาะ **GPU0** (RTX 2080 Ti) · ไม่แตะ GPU1 และ Ollama |
| โมเดล | PRISM (`prism-dr-5fold`, pins เดิมที่ตรวจแล้ว) เท่านั้น · ไม่รัน USPEC/RETFound ใน window นี้ |
| Requests สูงสุด | **3** (เฟส 1 = 1, เฟส 2 = 2) · ไม่มี retry · ถ้ามีครั้งใดล้มเหลวหรือไม่แน่ชัด หยุดทันทีและปิด window |
| ระยะเวลา | window เดียว · GPU lease **≤ 3,600 วินาที** (1 ชั่วโมง) · session จริง ≤ 2,640 วินาที (~44 นาที) · คาดใช้จริง ~20–30 นาที |
| ภาพ (TEST_ONLY workspace `ws_m1_63ed86c7…`) | เฟส 1: CFP `092d05e8…` · เฟส 2: UWF `8568e67e…` และ UWF `a48d90b1…` (ภาพเดิมที่อนุมัติไว้สำหรับ PRISM เมื่อวาน; ทั้ง 3 ภาพมี recorded hash แล้ว) |
| ผู้ตรวจ | `TEST_ONLY_ENGINEERING` (ไม่ใช่ผลแพทย์) |

หมายเหตุ: ภาพ CFP เป็นไฟล์ IDRiD สาธารณะที่อยู่ในโฟลเดอร์ consent ของ owner; PRISM บน UWF เป็นการใช้งานแบบทดลอง

## 3. ลำดับการทำงาน

**เฟส 1 — PRISM 1 เคส (CFP `092d05e8…`)**
1. เปิด Preview PRISM input ในหน้า Review → เตรียม input (ใช้ CPU ไม่นับ request)
2. กด Analyze PRISM 1 ครั้ง → ตรวจผลบันทึกลง PostgreSQL (readback อิสระ)
3. ปิด/เปิดแอปใหม่ แล้วเปิดเคสเดิม → ผล PRISM ต้องยังอยู่
4. ถ้าข้อใดไม่ผ่าน: **หยุด ปิด window** รายงานผล ไม่ไปเฟส 2

**เฟส 2 — ขยายอีก 2 เคส (เฉพาะเมื่อเฟส 1 ผ่านครบ)**
5. PRISM UWF `8568e67e…` → readback
6. ตัดการเชื่อมต่อ model ชั่วคราวระหว่าง request (ไม่ระหว่างที่กำลังส่ง) ยืนยันว่าหน้าแอปยังใช้ตรวจเองได้และไม่ถูกคิด request → ต่อใหม่ → PRISM UWF `a48d90b1…` → readback
7. ปิด session ยืนยัน `COMPLETE.json` (cleanup / window stop / ledger close = CONFIRMED) และ GPU0 คืนว่าง

## 5. สิ่งที่ต้องทำก่อนเปิด GPU (ไม่ใช้ GPU, ไม่คิด request)

ระบบบัญชี request ปัจจุบันรับ window ได้แค่ 2 ชื่อของวันที่ 23 (Server ปิดถาวรแล้ว, Local ยังเปิดใช้ไม่ได้)
จึงต้องทำงานเตรียมดังนี้ภายใต้การอนุมัติแผนนี้:

1. **Amendment บัญชี + โค้ด** (branch `fix/`): เพิ่ม Server window ใหม่ 1 ช่อง `HOSPITAL_M1_QA_SERVER_PRISM_20261024` ขนาด GPU ≤ 3,600 วินาที, ย้าย operation PRISM 3 รายการที่ยังไม่ได้ส่งเข้า window นี้ (ID ใหม่), cap ยังเป็น 549 เท่าเดิม, ไม่แตะ Local/Post-fix · มี tests + review อิสระก่อน merge
2. **Proposal ใหม่ (v3)** สร้างจากโค้ดที่ merge แล้ว และตรวจ dry run บน dr-train แบบ CPU
3. Deploy โค้ดโฮสต์ชุดใหม่ไปที่ dr-train และตรวจ identity แบบ CPU (pins ต้องตรง)
4. ตรวจในเครื่องว่าหน้า Preview PRISM ผ่านขั้น recorded attestation แล้ว (ไม่ส่งโมเดล)
5. ตรวจ GPU0 ว่าง ไม่มีงานทีมอื่น · ถ้า GPU0 ไม่ว่าง จะไม่เริ่มและแจ้งกลับ

**การยืนยันเพิ่มอีกครั้งเดียว:** กฎความปลอดภัยของบัญชีกำหนดให้ owner ยืนยัน "ลายนิ้วมือ" (SHA-256) ของ proposal v3 ที่ได้จริง
ผมจะส่งค่า hash พร้อมปุ่มยืนยันปุ่มเดียว ไม่มีการตัดสินใจใหม่ หลังกดแล้วผมเริ่ม GPU ตามแผนนี้และรายงานผลเมื่อจบ

## 6. ไม่อยู่ในแผนนี้

- ไม่รัน batch เดิม, USPEC/RETFound, หรือ post-fix
- ไม่เปิด QA_LOCAL
- ไม่เปลี่ยน pins, preprocessing หรือ semantics ทางคลินิก
- ผลเป็นหลักฐานทางวิศวกรรมบนข้อมูล TEST_ONLY ไม่ใช่การรับรองทางคลินิก
