# แผนปรับ UX/UI สำหรับจักษุแพทย์

สถานะ: **ร่าง รอ owner อนุมัติ** · 24 ตุลาคม 2569 · จัดทำโดย Claude Code
ที่มา: รีวิวหน้าจอจริง (Worklist, Confirm Image, Review, Clinician Review, Annotation Editor) และคำตอบของ owner ในแชต

## 1. เป้าหมาย

ผู้ใช้คือจักษุแพทย์ที่เวลาน้อยและไม่ถนัดเทคนิค หน้าจอต้องให้หมอใช้เวลากับภาพจอตา ไม่ใช่กับการตีความซอฟต์แวร์
ตรงกับหลักใน [design freeze](../milestone/m1/PRE_PHASE3_CLINICAL_UX_DESIGN_FREEZE.md): ดูภาพ → ตัดสินใจ → แก้เฉพาะที่จำเป็น → จบ → ภาพถัดไป

## 5. เฟส A: ใช้งานได้เร็ว (ไม่มีการแปลภาษา)

### A1 โหมดแพทย์ / ส่วนผู้ดูแล
- เมนูแพทย์: Worklist, Review เป็นค่าเริ่มต้น
- ส่วน "ผู้ดูแลระบบ" แยกกลุ่มใน sidebar: Datasets, Models & Audit, Settings
- ป้าย "Warnings" มุมขวาบนตอนนี้ขึ้นตลอด เพราะ `/health` ตอบ `PASS_WITH_WARNINGS` เสมอ จะเปลี่ยนเป็นป้ายเงียบ "Research use" และใช้สีเตือนเฉพาะตอนมีปัญหาจริง
- แก้หัวหน้า "Public & synthetic cases" ให้ตรงกับ workspace ที่ใช้อยู่
- ไฟล์หลัก: `navItems.ts`, `Sidebar.tsx`, `AppHeader.tsx`, `routeMeta.ts`, `useRuntimeHealth.ts`

### A2 ซ่อนข้อมูลเทคนิคจากหน้าแพทย์
- ย้ายส่วน "Model / runtime status" (รวม mock models และข้อความดิบอย่าง `REMOTE_NOT_CONFIGURED`) ไปไว้ที่ Models & Audit
- บรรทัด "Model: id - sha256…" เปลี่ยนเป็นชื่อที่อ่านง่าย เช่น "AI: USPEC (เกรดภาพ UWF)" ส่วนรายละเอียดเต็มอยู่ใน Processing details ที่ปิดไว้
- รวมข้อความเตือนที่ซ้ำกันเหลือบรรทัดเดียวต่อเรื่อง
- แท็บภาพ: เห็น Original และ AI evidence เป็นปกติ ส่วน Analysis area, Mask preview, Explainability ย้ายไปไว้ใต้ "เพิ่มเติม"
- Mask status ย้ายไปไว้ในส่วนเพิ่มเติม
- ไฟล์หลัก: `ReviewPage.tsx` และ Models & Audit page

### A3 ลดขั้นตอน
- **จำชื่อผู้ตรวจ:** แสดง "ผู้ตรวจ: ชื่อ · เปลี่ยน" ทุกจุด ถามครั้งแรกครั้งเดียวต่อเครื่อง ใช้ key เดิม `dr-support-screening.default-reviewer.v1` และยังไม่ใช่การยืนยันตัวตน
- **ปุ่มเกรด 0–4 และ Ungradable:** คลิกเดียวแทน dropdown คง Grade guide ไว้ และไม่เลือกเกรดตาม AI ไว้ล่วงหน้าเหมือนเดิม
- **เปิดภาพถัดไปอัตโนมัติ:** หลัง Finish เปิดเคสที่ยังไม่จบเคสถัดไป
- **Confirm Image:**
  - แสดงภาพขนาดใหญ่ในหน้าต่าง (ตอนนี้ไม่มีภาพเลย)
  - เพิ่มตัวเลือก "คุณภาพภาพ: ใช้ได้ / ใช้ไม่ได้" ซึ่งเรียก endpoint ยืนยันคุณภาพเดิม (`QUALITY_ACCEPTABLE` / `QUALITY_INADEQUATE`)
  - จุดนี้เปลี่ยน clinician workflow (พื้นที่ที่ได้รับการปกป้อง) owner อนุมัติแล้วในแชต จะบันทึกเป็น amendment ใน design freeze
- ไฟล์หลัก: `ReviewerField.tsx`, `ClinicianReviewPage.tsx`, `ConfirmImageDialog.tsx`, `AnnotationEditorPage.tsx`

### A4 ปุ่ม Finish ที่เสี่ยง
- เมื่อแพทย์ไม่ได้เพิ่ม finding แต่ AI มีข้อเสนอ ปุ่มจะเป็น "Finish — no findings added (21 AI suggestions not accepted)"
- ความหมายที่บันทึกเหมือนเดิม (REVIEWED_NONE_FOUND)
- ซ่อนกล่อง "Annotations confirmed / Reviewer: Not recorded" ที่ขัดกันเอง ให้แสดงเฉพาะเมื่อยืนยันจริง
- ไฟล์หลัก: `AnnotationEditorPage.tsx` (ใช้ `lesion_review.suggestion_count` ที่มีอยู่แล้ว)

### A5 ทางตันของ PRISM
- ปุ่มเตรียม PRISM ปิดไว้จนกว่าภาพจะยืนยันคุณภาพแล้ว พร้อมบรรทัดสั้น "ยืนยันคุณภาพภาพก่อนใช้ PRISM" และปุ่ม "คุณภาพภาพใช้ได้" ในที่เดียวกัน
- ข้อความผิดพลาดเป็นภาษาคน แทน "PRISM execution failed verification…"
- ฝั่ง client อ่าน `code` จากคำตอบ 409 ของ host ได้ เพื่อให้ log บอกสาเหตุจริง
- ไม่ลดเกณฑ์ของ host (ยังต้อง GRADABLE)
- ไฟล์หลัก: `PrismInputPreview.tsx`, `ReviewPage.tsx`, `prism_remote_bound.py`

### A6 Worklist
- สถานะชัดเจน: ยังไม่เริ่ม / กำลังทำ / จบแล้ว พร้อมตัวกรองและจำนวนต่อสถานะ แทน "27 need attention"
- เคสที่จบแล้วกรองตามเกรดสุดท้ายของแพทย์ (0–4, Ungradable)
- เคสที่ยังไม่ตรวจแสดงแค่ "AI พร้อม" เคสที่จบแล้วแสดงเกรดของแพทย์
- แถวเตี้ยลง ให้เห็นเคสมากขึ้นต่อหน้าจอ
- ไฟล์หลัก: `WorklistPage.tsx`, `WorklistTable.tsx`, `worklistModel.ts`, `AIResultCell.tsx`

### A7 สี KKU
- ใช้ token ที่มีอยู่แล้วใน theme (`accent.institutional*`) ตามค่าเริ่มต้นในข้อ 3 ไม่เพิ่มสีใหม่
- อัปเดตหมายเหตุ "Legacy alignment" ใน DESIGN.md §2.3 ให้ตรงกับ theme ปัจจุบัน

## 6. เฟส B: สลับภาษาไทย/อังกฤษ

- เพิ่มชั้นแปลภาษาแบบเบา (dictionary ต่อหน้า) ตอนนี้ไม่มีระบบแปลเลยและข้อความเป็นภาษาอังกฤษทั้งหมด
- ปุ่มสลับภาษาใน header จำค่าไว้ต่อเครื่อง
- รายการศัพท์ที่คงเป็นอังกฤษ เช่น DR grade, Microaneurysm, Hemorrhage, Hard/Soft exudate, CFP, UWF, PRISM, RETFound, USPEC, Ungradable
- เขียนข้อความไทยด้วย `kien-thai` และ `write-thai` แล้วให้ owner หรือแพทย์ตรวจคำก่อนปล่อย
- ทดสอบว่าชื่อผู้ตรวจและข้อความไทยแสดงถูก (Unicode) และไม่ล้นปุ่ม

## 7. สิ่งที่ไม่เปลี่ยน

- เกรดสุดท้ายยังเป็นของแพทย์ AI ยังเป็นแค่ข้อเสนอ และไม่เลือกเกรดตาม AI ไว้ล่วงหน้า
- ความหมายที่บันทึกในฐานข้อมูล (สถานะการตรวจ, provenance, revision) และ API
- เกณฑ์ความปลอดภัยของ PRISM และการรับภาพ
- ตำแหน่งพิกัดบนภาพ การซูม และการแยก AI/มนุษย์บนภาพ

## 8. เกณฑ์ผ่าน

- **ทดสอบโค้ด:** frontend tests ของหน้าที่แก้ผ่านทั้งหมด typecheck และ build ผ่าน backend suite ผ่าน
- **วัดภาระงาน:** วัดก่อนและหลังตาม design freeze §9
  - คาดว่าเดิมใช้ประมาณ 11–12 คลิกและพิมพ์ 1–2 ช่องต่อเคสปกติ
  - เป้าหลังเฟส A คือประมาณ 7 คลิกและไม่ต้องพิมพ์ (ตัวเลขจริงจะวัดใหม่)
- **ทดลองต่อเนื่อง:** 10 เคสใน TEST_ONLY workspace
- **ตรวจ UI:** ผ่าน checklist ของ `no-slop-ui` และ DESIGN.md ถ้าไม่ผ่านตั้งแต่ 2 หมวดขึ้นไป ต้องแก้ก่อน
- **ตรวจบนเครื่องจริง:** ตรวจในเบราว์เซอร์จาก build บน main หลัง merge
- **แนะนำเพิ่ม:** ให้จักษุแพทย์จริง 1–2 ท่านลองใช้และจับเวลา (owner เป็นผู้นัด)

## 9. ขั้นตอนทำงาน

- แต่ละเฟสทำบน branch `fix/` แยก → ทดสอบ → review อิสระ → merge → build `frontend/dist` ใหม่บน main → ตรวจในเบราว์เซอร์
- ไม่ใช้ GPU และไม่แตะข้อมูลจริงนอก TEST_ONLY workspace
- รายงานสั้นๆ เมื่อจบแต่ละเฟส
