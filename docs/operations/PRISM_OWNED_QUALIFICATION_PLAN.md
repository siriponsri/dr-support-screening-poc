# Owned PRISM qualification plan — disabled proposal

The additive candidate is integrated for offline review only. Both
worker_factory and register_fixed_owned_runtime still raise. The template at
[examples/prism-owned-qualification.disabled.json](examples/prism-owned-qualification.disabled.json)
is an inventory/proposal, not a consumed configuration format or an activation
flag. enabled=false cannot be changed to turn on the runtime. No bootstrap was
executed. Placeholders name existing approved credential readers, never secrets.

The integration corrects two independent review findings. A supervisor-constructor
or watchdog-start failure retains the exact verified spawn-owned handle, requests
bounded TERM/force cleanup and requires close_confirmed. Unknown identity or a
surviving child produces explicit unconfirmed/quarantine failure, never success
or a restart. Cleanup liveness uses the pinned handle without requiring resource
telemetry. No unrelated PID or process group may be signaled.

Resource sampling now shares a 0.5-second aggregate deadline across both commands
and the RSS read; each command timeout is at most 0.2 seconds and shrinks to the
remaining budget. Late results are rejected, never reported healthy. This leaves
margin under the one-second monitoring policy, but real OS scheduling, process
creation and filesystem I/O bounds remain unqualified until Phase A. No software
timeout is claimed to guarantee interruption of an uninterruptible OS call.

## Phase A: future fake-worker Linux transport/supervision

Requires separate permission for source installation, temporary owned process and
loopback listeners. It requires **zero real model imports, GPU loads or inference**.
Use a reviewed fake executor reporting synthetic pins and serial fake jobs, with
the real Linux pidfd child adapter, watchdog and real bounded HTTP transport.
The production worker factory remains disabled; any fake-only launcher needs its
own reviewed argv/code digest and cannot accept a real model constructor.

1. Read-only prerequisites: interpreter/source hashes, existing token-reader
   reference, fresh journal/output paths, Linux pidfd support, exact project root,
   existing forward and availability of loopback7862/17860. A foreign listener
   stops the attempt; do not kill/rebind or scan/attach another process.
2. Spawn exactly one owned fake child with fixed argv/environment; capture parent,
   birth marker, scope, command hash and pidfd ownership. Never attach by PID.
   Require exact loaded epoch/pins and listener inode ownership before preparation.
3. Run serial synthetic prepare/execute/challenge/grant/status through the actual
   fixed app. Record hashes and monotonic timestamps without images, tokens,
   filenames or patient data in diagnostics. Prove repeated/stale submission rejects
   before fake ROI entry and preparation does not rerun mask detection.
4. Separately exercise bounded slow-header/body/response streams, disconnect after
   grant, absent status, foreign-listener rejection, fake resource-limit reports,
   cancelled/draining jobs and an owned hung fake child. Use a finite reviewed
   matrix/cap, not retries until success. Resource thresholds are injected fake
   observations here; they do not qualify real PRISM GPU resource sampling.
5. Verify unknown outcome retains durable quarantine across cooperative restart.
   Require STOPPED plus close_confirmed for the owned child. Preserve unresolved
   evidence/journal; timeout, cancel ACK or a new epoch never clears authority.

Acceptance: owned-only signaling/reaping, no extra worker or implicit restart,
absolute transport bounds measured on actual Linux I/O, independent watchdog
behavior and terminal/entry proof. Fake tests on Windows do not establish these.
OS crash/power-loss recovery remains a distinct qualification item.
