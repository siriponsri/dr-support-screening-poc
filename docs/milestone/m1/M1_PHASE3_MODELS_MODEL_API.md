## 3. Interfaces, invariants and non-goals

**Consumes:** Phase 2 versioned original/masked-analysis/transform input and opt-in inference request, explicitly identified capability/bundle identity (version and digest), authorized local checkpoints; existing remote provider request shapes and profile configuration. **Produces:** task-specific typed grade/finding suggestions or explicit unavailable/error/unsupported outcome, model ID/version/checkpoint digest/domain/input modality/taxonomy/class order/preprocessing and postprocessing versions, quality warnings and original-coordinate geometry, plus **versioned explanation evidence when supported** (for NB01, patch/MIL attention scores/grid; for lesion providers, proposal/review-box evidence). Explanation evidence is AI provenance, not a physician label. Physician review remains distinct and PostgreSQL persists raw predictions and later human lineage.

**B01 source-origin gap:** at the pinned commit, `services/model_api.py` `RemotePredictRequest.source_type` and `contracts/_schema.py` `Provenance.source_type` allow only `PUBLIC`/`SYNTHETIC`; `providers/remote.py` forwards `image.source_type` and validates returned image SHA-256. `services/admission.py` currently constructs workspace images as `PUBLIC`. These facts are independent of UWF/CFP modality and selected model. The current wire contract does not establish truthful authorized-hospital origin/permission. P2-1/P1-A/P3-4/P4-3/P5-1/3/5 must agree on a data-steward/owner-reviewed representation and access policy before hospital inference; **no settled new enum is specified here**. Do not relabel hospital data as `PUBLIC`/`SYNTHETIC` because deidentification or a pseudonym does not make it public. Public/synthetic engineering remains available.

**Current protected interface:** `APP_PROFILE=review`, `MODEL_RUNTIME=remote` versus CUDA `APP_PROFILE=model_api`, `MODEL_RUNTIME=local`, one worker; `/health`, `/v1/models`, `/v1/predict/dr`, `/v1/predict/lesions`; repository current `PORT=7860`. Existing `dr_support/services/{model_api,model_gateway}.py`, `contracts/model_gateway.py`, `providers/remote.py`, `tests/test_{bridge,remote,profiles}.py`. The extracted deployment **code** at `research/deployment_prototype/` is a prototype with `/predict:8000`; it does not replace ADR-0002 Bridge v1. The separately supplied physical deployment diagram's whole-plan approval status is `UNKNOWN`: record owner provenance by component (DB/RDS UAT, application hosts, QA/PRD L4 model hosts, VLAN/network, `/data/models`, promotion) at P3-5/P5-5. A hospital-local GPU host and Phase 1's AWS RDS UAT decision address different components and need not conflict. Any route/port/schema change needs a versioned proposal, migration/compatibility tests and owner review.

**Non-goals:** selecting dependency pins by inspection, activating ROI cropper merely because weight exists, interpreting all-true mask as gradeability, treating NB01 attention as lesion localization, enabling autonomous DME/referral or longitudinal change rules, changing preprocessing as a presumed neutral refactor, copying checkpoints into Git, clinical or production readiness from checksum alone, or automatically retraining/overwriting an enabled model from newly saved hospital labels. Confidential weights stay on authorized server only. Manual workflow must continue on any inference failure; never synthesize normal grade 0 or an empty finding set that appears physician-reviewed.

### 4.1 NB01 model lineage and M1→M2 evolution contract

The M1 application consumes a **qualified immutable model version**. It does not update weights online when a physician saves a label. A future hospital-domain training round must be a separate, authorized run that records at minimum: parent checkpoint digest, training code/revision, preprocessing/mask version, physician-confirmed dataset snapshot ID and policy/taxonomy version, patient-grouped split identity, training/validation metrics, resulting checkpoint digest and promotion decision.

The expected progression is `NB01 model version → M1 physician-confirmed snapshot → new fine-tuning run → new model version`. The original enabled artifact remains available for rollback/comparison until the new version passes its own qualification. Phase 4 owns reproducible training-data snapshots; M2 is the expected milestone for hospital-domain model improvement and clinical-screening behavior. No patient data are sent to a training environment without separate data-steward authorization.

## 6. Failure/recovery, dependencies and decisions

Classify failure by evidence before changing any artifact state; all affected capabilities become unavailable with redacted diagnostics and manual work continues. `VERIFIED_BYTES` is not erased by a runtime error unless bytes or the expected identity are actually shown to have changed. No automatic delete, reacquisition, bundle reselection by mtime, expected-hash rewrite or deserialization bypass.

| Observed failure | Result and next gate |
|---|---|
| Missing checkpoint | Acquisition incomplete; do not load. Keep expected manifest identity and request authorized acquisition (P3-1). |
| Invalid expected SHA-256 format | `INVALID_EXPECTED_HASH`: metadata verification blocked; retain the malformed source value and seek manifest/custodian correction, never substitute observed digest. |
| Observed bytes mismatch a valid expected digest | `HASH_MISMATCH`: integrity failed for that file; stop its use, retain bounded evidence, investigate source/transfer with custodian. Do not call it verified. |
| Verified bytes but loader/compatibility/CUDA NMS failure | Runtime qualification failed (P3-3), **not** proof of byte corruption. Preserve byte receipt and investigate build, loader, dependency or device before a controlled retry. |
| Security advisory or trust gate not cleared | Deserialization blocked independently of byte integrity; security owner decides remediation/authorized mitigated research path before any initial load. |
| OOM, timeout or remote transport failure | Runtime/resource/request failure. Preserve earlier byte status unless recheck finds changed bytes; record device/request context and retry only under approved operating profile. |

Preserve previous authorized artifacts and allow manual work; no silent fallback to a different bundle selected by mtime. Offline network outage and remote timeout remain explicit, not grade 0. Retain separate immutable input, intermediate mask/transform and output receipts for debugging without patient-level payload in planning evidence. Rollback means redeploy a previously qualified version after authorization and re-check exact digest; never rewrite prior review history.
