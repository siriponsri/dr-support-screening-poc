The clinical problem

Screening volume grows faster than specialist attention.

The Workbench is designed to make review more structured, traceable, and focused on the cases that need human attention.

Many images

Routine fundus photographs arrive with different quality, context, and clinical urgency.

Limited time

Ophthalmologist attention is the scarce resource. The interface should reduce avoidable navigation and re-entry work.

Human judgment

The product supports a clinician's decision; it does not make an autonomous referral or treatment decision.

Conceptual framing · not a local outcome claim
Clinical problem framing adapted from owner-provided ophthalmologist deck; claims are intentionally non-quantitative.
Positioning

The system is an assistive review layer above the image.

It is

  • review support
  • AI evidence with visible provenance
  • human final decision
  • dataset and audit workflow

It is not

  • autonomous diagnosis
  • automatic treatment decision
  • automatic patient notification
  • a replacement for ophthalmologist judgment

Two tasks, two evidence types

AI evidence stays below the human review decision.

RETFound → DR grade suggestion

Global classification evidence for a five-class DR suggestion. The model score is not a calibrated clinical probability.

PRISM-DR → lesion ROI suggestions

Object-level evidence for Microaneurysm, Hemorrhage, Hard exudate, and Soft exudate.

Clinician review remains authoritative.

Evidence can inform inspection, correction, or escalation. It cannot confirm a case by itself.

Uncertainty is part of the workflow

Unclear image ≠ normal image. No detection ≠ no lesion.

Image quality

When assessment is inadequate, the correct action is to recognize that limitation and follow the local clinical pathway. The product does not silently convert uncertainty into normality.

Model output

An empty PRISM-DR result is an empty suggestion set, not proof that a lesion is absent. Human review remains the authority.

The UI should make uncertainty legible without pretending to calibrate it.

On-premise oriented deployment

The workstation and GPU Model API have different trust and runtime roles.

Windows review workstation

Browser UI, local review state, `APP_PROFILE=review`, `MODEL_RUNTIME=remote`, no model weights.

Protected hospital LAN

Only the approved network boundary connects the workstation to the service.

Linux GPU Model API

`APP_PROFILE=model_api`, verified local assets, CUDA device, one worker, controlled service.

The workstation can keep operating locally when remote model assistance is unavailable; model evidence is optional.
