## Scene 03 — Image intake and sampling

เวลาประมาณ: 90 วินาที

### เป้าหมาย

อธิบายขอบเขตการรับภาพ ตาราง monitoring ของทีม และแยกให้ชัดว่าข้อไหนเป็นซอฟต์แวร์ ข้อไหนเป็นนโยบาย ข้อไหนเป็นแค่เป้าหมาย

### บทพูด

[เปิด slide]

[กด Space]

[ชี้ที่ ไดอะแกรมซ้าย]

ภาพอยู่ใน storage ของโรงพยาบาล คุณหมอหรือผู้ได้รับอนุญาตเป็นคนเลือก ส่งผ่านขั้นตอนที่โรงพยาบาลอนุมัติเข้า input folder ของ Workspace ระบบอ่านเฉพาะ folder นี้ และอ่านแค่ชั้นบนสุด ทีมเองก็ไม่ได้เข้าไปค้นใน storage

[กด Space]

[ชี้ที่ ตารางสองตาราง]

ตารางที่ทีมใช้ติดตามมีแค่สองตาราง คือเพศเทียบกับ Refer/Not-refer และตาซ้าย/ขวาเทียบกับ Refer/Not-refer ไม่ได้ทำเป็น quota 18 ช่อง

สำหรับ POC ตั้งเป้าให้ Refer อยู่ราว 40 ถึง 60 เปอร์เซ็นต์ ซึ่งไม่ใช่ความชุกของโรงพยาบาล และไม่ใช่ sample size ที่คำนวณเพื่อ validation

[กด Space]

[ชี้ที่ ป้าย SW, OWN, TGT, OPEN ตามลำดับ]

จุดที่สำคัญที่สุดสำหรับนักพัฒนาคือ ใน Workbench **ไม่มี field** สำหรับ Refer/Not-refer หรือเพศเลย ตาซ้าย/ขวาได้มาจาก Confirm Image และไฟล์ซ้ำตรวจได้จาก SHA-256 ส่วนเรื่องที่ว่าจะผูก source class เข้ากับภาพยังไง ยังเป็น open decision ของเจ้าของโครงการ ห้ามเขียน field นี้เพิ่มเองโดยไม่มี spec

### ถ้ามีเวลาน้อย

"คนเลือกภาพ ทีมเป็นคนติดตามสัดส่วน ระบบแค่รับภาพเข้า Refer/Not-refer กับเพศไม่ได้อยู่ในระบบ วิธีผูกข้อมูลยังรอเจ้าของโครงการตัดสินใจ"

### ห้ามพูดเกิน claim

- ห้ามพูดว่าระบบนับ Refer/Not-refer หรือเพศให้
- ห้ามพูดว่า 40–60 % เป็นข้อกำหนดทางคลินิก

### เป้าหมาย

อธิบายกฎการรับภาพ และว่าคนเป็นผู้ยืนยันขั้นสุดท้าย

### บทพูด

[เปิด slide]

[กด Space]

[ชี้ที่ ลำดับใน diagram]

ขั้นตอนคือกด scan แล้วระบบจะอ่านไฟล์ชั้นบนสุด คำนวณ SHA-256 ตรวจ format และคัดกรองแบบหยาบ ๆ จากนั้น resolver จะเสนอรหัสผู้ป่วยกับตาจากชื่อไฟล์ และสุดท้ายคุณหมอ Confirm Image

[กด Space]

ไฟล์ที่เนื้อหาเหมือนกันทุก byte จะรวมเป็นเคสเดียว ถ้า scan ใหม่ การตัดสินใจที่คนทำไว้แล้วจะไม่ถูกทับ ภาพจะผ่านอัตโนมัติได้ต้องผ่านสัญญาณครบสี่ข้อ ถ้าไม่ครบก็เป็น NEEDS_REVIEW ไม่ได้ถูกปฏิเสธ ส่วน DICOM ที่ไม่ใช่ภาพจอตา จะขึ้นว่า Unsupported modality

### ถ้ามีเวลาน้อย

"รับภาพแบบระวัง ไฟล์ซ้ำตรวจด้วย hash และการตัดสินใจของคนไม่ถูกทับ"

### ห้ามพูดเกิน claim

- การคัดกรองอัตโนมัติไม่ใช่การประเมิน gradability

## Scene 09 — Inference

เวลาประมาณ: 60 วินาที

### เป้าหมาย

อธิบายเส้นทาง inference และความต่างระหว่าง source SHA กับ analysis SHA

### บทพูด

[เปิด slide]

[กด Space]

ก่อน inference ระบบเช็กก่อนว่าภาพนี้ส่งวิเคราะห์ได้ไหม แล้วสร้างภาพสำหรับวิเคราะห์ขึ้นมาอีกชุด ส่งไป Model API โดยมี timeout 30 วินาที ผลกล่องรอยโรคที่ได้กลับมาจะถูกแปลงพิกัดกลับเป็นพิกเซลของภาพต้นฉบับ

[กด Space]

[ชี้ที่ ตาราง identity]

source SHA คือ hash ของไฟล์ต้นฉบับ และใช้เป็นตัวตนของเคส ส่วน analysis SHA คือ hash ของไฟล์ที่ส่งให้โมเดลจริง ถ้าเป็น JPEG หรือ PNG สองค่านี้จะเท่ากัน ถ้าเป็น TIFF หรือ DICOM จะไม่เท่ากัน ถ้าภาพใหญ่เกิน 20 MB ระบบจะไม่ย่อภาพให้เอง

### ถ้ามีเวลาน้อย

"ต้นฉบับมี hash ของตัวเอง ภาพที่ส่งให้โมเดลก็มี hash ของตัวเอง และพิกัดทุกอย่างอิงภาพต้นฉบับ"

### ห้ามพูดเกิน claim

- score ไม่ใช่ความน่าจะเป็นที่ calibrate แล้ว

เวลาประมาณ: 60 วินาที

### บทพูด

[เปิด slide]

[กด Space]

[ชี้ที่ ส่วน LAN]

ทุกอย่างอยู่ใน LAN ของโรงพยาบาลที่มีการป้องกัน ส่วน TLS และ firewall เป็นงานของโครงสร้างพื้นฐานโรงพยาบาล ใช้ internet แค่ตอน setup กับ CVAT ซึ่งไม่บังคับ

"ใช้ LAN ที่ป้องกันไว้ ตรวจไฟล์ก่อน start ไม่มี secret ใน browser และยังไม่มี login"
